# Running the pick-and-place demo

Visualises the full pipeline on a Franka Panda in RViz 2 and Gazebo, with the
generated objects that were scored in Table I of the paper.

## What you will see

- **Gazebo window.** The generated object spawns on the brown table in
  `panda_eval_world`; on every cycle a different random object (hammer, mug,
  L-shape, dumbbell, …) is spawned in its place.
- **RViz 2 window.** The Panda's `RobotModel` runs an 8-stage pick-and-place:
  *ready → pre-grasp → grasp → lift → transport → place → retract → ready*.
  The driver publishes a `CollisionObject` for the table into MoveIt 2's
  planning scene, so RRTConnect plans **around** the table (the arm no
  longer dives into the brown box). While the object is grasped a marker
  travels with the gripper.

## Prerequisites

Same as `REPRODUCE.md` plus a display server. Build the workspace first:

```bash
cd ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select generated_objects_eval
source install/setup.bash
cd ..
```

Ensure a manifest exists (or build one):

```bash
# top-k controls how many objects per method end up in the rotation;
# bump it to 100 if you want the demo to cycle through more shapes.
python3 scripts/build_eval_manifest.py \
    --budget 1500 --top-k 25 --seed 42 \
    --out output/seed_42/eval_manifest.json
python3 scripts/patch_sdf_collision.py \
    --manifest output/seed_42/eval_manifest.json
```

## 1. Full pick-and-place with physics (Recommended)

This is the canonical demo: the Panda actually moves under `gz_ros2_control`,
RViz mirrors physics, and a different random object spawns each cycle.

```bash
ros2 launch generated_objects_eval visual_demo.launch.py \
    use_gz_control:=true
```

The launch picks `output/seed_42/eval_manifest.json` automatically; override
with `manifest:=/abs/path/eval_manifest.json` to point elsewhere. Stop with
Ctrl-C.

The driver shuffles the manifest at startup and again every full pass, so
the first cycle is rarely the same shape twice. Pin a particular object
with `--object-index N` (any positional arg) or fix the shuffle with
`--seed`:

```bash
# pin to hammer (manifest entry 7) for repeatable recording
ros2 launch generated_objects_eval visual_demo.launch.py \
    use_gz_control:=true \
    driver_extra_args:="--object-index 7"      # not yet exposed; edit launch
```

What the launch brings up:

1. `gz sim -r` on `panda_eval_world` (windowed); the Panda is spawned via
   `ros_gz_sim create -topic /robot_description`.
2. `gz_ros2_control` inside gz starts the `controller_manager`; spawners
   activate `joint_state_broadcaster`, `panda_arm_controller`
   (`JointTrajectoryController`), and `panda_hand_controller`.
3. `robot_state_publisher` + a static `world -> panda_link0` TF.
4. `rviz2` with the bundled `demo.rviz` (RobotModel + Marker displays).
5. `demo_plan_driver`: spawns one random object in gz, publishes the table
   as a `CollisionObject` into `/planning_scene`, plans each stage with
   MoveIt 2 (RRTConnect/OMPL), and hands the trajectory to
   `panda_arm_controller` via `MoveItPy.execute()`.

## 2. RViz-only animation (faster, no physics)

If you only need RViz playback (no Gazebo physics, no real controllers):

```bash
ros2 launch generated_objects_eval visual_demo.launch.py     # use_gz_control:=false (default)
```

The driver animates the planned trajectory directly on `/joint_states`. This
mode is what's recorded for the *rviz_motion_plan.mp4* clip on the project
page.

## 3. Gazebo drop-and-settle (Gazebo only, no Panda)

The *gz_drop_settle.mp4* clip is generated by the stability evaluator:

```bash
# Terminal A: world
ros2 launch generated_objects_eval stability_world_gui.launch.py

# Terminal B: stability eval (use --max-objects to keep videos short)
ros2 run generated_objects_eval gazebo_stability_eval \
    --manifest $(pwd)/output/seed_42/eval_manifest.json \
    --out /tmp/gz_drop_settle.json --max-objects 6
```

## 4. Archetype tour (gz_sim only)

Renders the *archetype_tour.mp4* clip showing one object per archetype
settling on the table:

```bash
# Terminal A
ros2 launch generated_objects_eval stability_world_gui.launch.py

# Terminal B
python3 scripts/archetype_tour.py \
    --manifest output/seed_42/eval_manifest.json \
    --methods cem fixed_cad cmaes --per-method 4 --settle-s 3.0
```

### Option A — `ffmpeg` + x11grab

```bash
# 1. Find the gz_sim or RViz window geometry
WIN=$(xdotool search --name "Gazebo Sim" | head -1)        # or "RViz" / "Demo"
xdotool getwindowgeometry --shell $WIN

# 2. Record (adjust :0.0+X,Y from the previous output)
ffmpeg -f x11grab -framerate 30 -video_size 1280x720 -i :0.0+100,80 \
       -c:v libx264 -pix_fmt yuv420p -crf 23 \
       docs/videos/side_by_side.mp4
```

### Option B — OBS Studio (Recommended for side-by-side)

Add one *Window Capture* source per pane (Gazebo + RViz), arrange them
side-by-side in one scene, hit Start Recording, then run the launch file.
Set output → MP4 → 30 fps to match the project page.

### Option C — Gazebo's built-in recorder

`Settings → Video Recording → Start` in the `gz sim` window. Saves to
`~/.gz/sim/videos/`. Useful for the *gz_drop_settle.mp4* clip when you
only need the gz pane.

After recording, name the files exactly as in the table above; the project
page (`docs/index.html`) wires those filenames in.

## Common gotchas

### RViz starts but the Panda doesn't render

- `ros2 topic echo /joint_states --once` — should print 9 joint positions.
- `ros2 topic echo /tf_static --once` — should include `world -> panda_link0`.
- If RViz Fixed Frame complains, set it to `panda_link0` (Displays → Global Options).

### NVIDIA `libEGL` warnings — `failed to create dri2 screen`

On hybrid-graphics laptops, gz_sim picks the wrong renderer:

```bash
# a) Force gz to render through the NVIDIA GPU
__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia \
ros2 launch generated_objects_eval visual_demo.launch.py manifest:=...

# b) Fall back to OGRE 1.x (no Vulkan/EGL needed)
#   edit launch/visual_demo.launch.py and replace
#     "--render-engine", "ogre2"  ->  "--render-engine", "ogre"

# c) Software rendering (always works, slow)
LIBGL_ALWAYS_SOFTWARE=1 ros2 launch generated_objects_eval visual_demo.launch.py manifest:=...
```

### "Missing virtual_joint" warning every second

The Panda SRDF declares a virtual_joint linking `world` to `panda_link0`;
until the static TF is published, MoveIt's planning_scene_monitor logs this.
Our launch starts `static_transform_publisher` automatically; if you see the
warning, that node failed to start (check
`~/.ros/log/*/static_transform_publisher*.log`).

### `CheckStartStateCollision' failed` in the planning log

The Panda is being evaluated at all-zero joints (self-collision). The driver
pins the start state to the SRDF `ready` group state; if you see this,
rebuild with `colcon build --packages-select generated_objects_eval`.

### Stale `gz sim` instances

```bash
pkill -KILL -f "gz sim -s -r"   # precise pattern - the broad "gz sim" can match unrelated processes
pkill -KILL -f "gazebo_stability_eval"
pkill -KILL -f "moveit_planning_eval"
```
