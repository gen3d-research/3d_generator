Reproducing the numbers

End-to-end, in under thirty minutes on a single CPU. Three independent stages each produce part of Table II.

Prerequisites

  • Ubuntu 24.04 (Noble) with ROS 2 Jazzy installed. The Debian binaries from packages.ros.org work.
  • The following ros-jazzy-* packages: moveit, moveit-py, moveit-resources-panda-description, moveit-resources-panda-moveit-config, ros-gz-sim, robot-state-publisher, tf2-ros.
  • Python 3.12 with numpy, scipy, trimesh, pyyaml, matplotlib, and cma (for the CMA-ES baseline). Install with pip install --user trimesh pyyaml cma matplotlib.
  • About 1 GB of free disk for the per-seed manifest dirs.
sudo apt install -y \
    ros-jazzy-moveit ros-jazzy-moveit-py \
    ros-jazzy-moveit-resources-panda-description \
    ros-jazzy-moveit-resources-panda-moveit-config \
    ros-jazzy-ros-gz-sim ros-jazzy-robot-state-publisher \
    ros-jazzy-tf2-ros latexdiff
pip install --user --break-system-packages trimesh pyyaml cma matplotlib

Clone

git clone https://github.com/xya22er/3d_generator.git
cd 3d_generator

Everything below assumes the working directory is the repository root.

Build the ROS 2 workspace

cd ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select generated_objects_eval
source install/setup.bash
cd ..
Tip. Future shells need both source /opt/ros/jazzy/setup.bash and source ros2_ws/install/setup.bash in that order.

Three stages

1 Build the per-method manifest of objects + grasps

For each method (CEM, CMA-ES, GA, random search, fixed CAD), this trains under a 1500-evaluation budget, exports the top-25 objects to URDF + SDF + meshes under output/seed_42/manifest_objects/, and synthesises grasp candidates for each. The SDF collision geometry is then rewritten to the visual mesh's AABB (DART can't ingest normal-less OBJs). 

python3 scripts/build_eval_manifest.py \
    --budget 1500 --top-k 25 --seed 42 \
    --out output/seed_42/eval_manifest.json
python3 scripts/patch_sdf_collision.py \
    --manifest output/seed_42/eval_manifest.json

Repeat with --seed 43 and --seed 44 for the multi-seed table.

2 Python-level evaluation

Produces the suitability score, force-closure grasp success rate, feature diversity, and Chamfer diversity per method. Output goes to a single JSON consumed by the aggregation step. 

python3 scripts/run_unified_eval.py \
    --budget 1500 --top-k 100 --seed 42 \
    --out output/seed_42/unified_eval.json

3a MoveIt 2 motion-planning evaluation

Brings up robot_state_publisher, home_joint_state_publisher, a static world → panda_link0 TF, and the moveit_planning_eval node. The node loads each grasp's pre-grasp pose and asks RRTConnect for a joint-space plan from the Panda's SRDF ready configuration. 

cd ros2_ws && source install/setup.bash && cd ..
ros2 launch generated_objects_eval moveit_planning_eval.launch.py \
    manifest:=$(pwd)/output/seed_42/eval_manifest.json \
    out:=$(pwd)/output/seed_42/moveit_results.json \
    max_objects:=0
Heads-up. The moveit_py 2.12.x shutdown segfaults after the JSON is written. The scripts/run_multi_seed.sh wrapper polls for the JSON and kills the launch immediately so the next stage can start; if you invoke the launch by hand, watch for "Wrote 125 results to ..." and Ctrl-C.

3b Gazebo dynamic-stability evaluation

Boots gz_sim headless with the bundled panda_eval_world (ground + table) and spawns each generated object on the table for a 2.5 s settle. An object is stable iff tilt < 25° and drift < 5 cm. 

# In one terminal:
ros2 launch generated_objects_eval stability_world.launch.py

# In another terminal:
cd ros2_ws && source install/setup.bash && cd ..
ros2 run generated_objects_eval gazebo_stability_eval \
    --manifest $(pwd)/output/seed_42/eval_manifest.json \
    --out $(pwd)/output/seed_42/gazebo_stability.json

All seeds in one go

scripts/run_multi_seed.sh chains stages 1–3 across multiple seeds, killing stale gz_sim instances before every seed (the gz transport routes service calls non-deterministically across same-world instances otherwise): 

bash scripts/run_multi_seed.sh 42 43 44

About 20 minutes per seed on a recent laptop CPU. Logs land in output/seed_<N>/{moveit,gazebo,gz_world}.log.

Aggregate

python3 scripts/aggregate_seeds.py 42 43 44 \
    --out output/aggregated.json
cp output/aggregated.json docs/data/results.json   # refresh the project page

The aggregator prints a markdown table identical to Table II in the paper and writes a JSON consumed by the results table on this site.

Verify your numbers

Reproduction tolerance is ±3% on every cell of Table II across seeds 42/43/44. If a number drifts by more than that, the most likely cause is one of:

  • Stale gz sim instances from a previous run stealing /world/.../create service calls. Run pkill -KILL -f "gz sim" and re-launch.
  • CheckStartStateCollision failures in the MoveIt log: the Panda is being evaluated at all-zero joints (which puts it in self-collision). The launch uses home_joint_state_publisher + SRDF set_start_state("ready") to avoid this; if those got bypassed (e.g. you replaced the launch file), restore them.
  • Mesh normals missing in the exported collision OBJ. Run patch_sdf_collision.py to rewrite collisions as AABB primitives.
